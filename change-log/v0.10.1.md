### Highlights

- **Deadline-driven elections and heartbeats.** Openraft replaces the periodic
  ticker with separate timers for elections and leader heartbeats. Runtime
  switch changes wake RaftCore immediately. Applications can use `Trigger::tick()`
  to drive heartbeat checks for many Raft groups from one timer.
  ([#2304](https://github.com/databendlabs/openraft/issues/2304))
- **Conditional batch writes.** `Raft::write_many()` supports an optional
  responder per entry. Both batch write APIs accept `WriteOption` to require an
  expected leader. Openraft accepts or rejects the batch as a whole, but entries
  still commit individually: a leadership change can leave only a prefix
  committed. `Raft::write()` also accepts `.with_option()`.
  ([#2321](https://github.com/databendlabs/openraft/issues/2321))
- **Opt-in relaxed leader reads.** `LinearizerOption::with_relaxed(true)` waits
  for the leader's no-op to apply without also waiting for the committed log ID,
  reducing read latency when apply lags behind replication. The reduced barrier
  applies only on the issuing leader; follower reads still use the standard
  barrier. Before requesting relaxed reads, restart **every node** with
  `Config::enable_relaxed_read` set to `Some(true)` and ensure the state machine
  makes writes visible before acknowledging them. Enabling the setting can
  increase follower apply lag because followers wait for the leader to apply
  entries first.
  ([#1267](https://github.com/databendlabs/openraft/issues/1267))
- **Faster state-machine apply and lower idle memory.** The worker merges
  contiguous apply requests, reads the next batch while applying the current one,
  and publishes completed progress without waiting for the next read. Smaller
  initial queues and runtime futures reduce memory use for deployments with many
  mostly idle groups.
  ([#2309](https://github.com/databendlabs/openraft/issues/2309),
  [#2323](https://github.com/databendlabs/openraft/issues/2323),
  [bc383014](https://github.com/databendlabs/openraft/commit/bc3830148e5ccaf418390a2e8e0ea0695fa87159))

### Other notable changes

- `RaftMetrics` and `RaftServerMetrics` expose `last_leader_contact` on followers
  and learners. It indicates recent contact, not quorum health or log catch-up.
  The `apply_batch` metric now records one sample per completed state-machine
  `apply()` call rather than per queued command.
  ([04cf76af](https://github.com/databendlabs/openraft/commit/04cf76af62b5cde2a49234c846be612f8c173583),
  [#2346](https://github.com/databendlabs/openraft/issues/2346))
- `ApplicationSuite` lets storage implementers check that different apply batch
  boundaries produce the same state, progress, membership, and responses.
  ([4ecc36a1](https://github.com/databendlabs/openraft/commit/4ecc36a1f5bbb707dbf86da1e19c342b0dbbec88))
- `declare_raft_types!` now accepts overrides for `Responder<T>` and `Batch<T>`.
  ([c5096d12](https://github.com/databendlabs/openraft/commit/c5096d127681dfd31e465de1fdee8ab59948c125))
- Fixed cancellation of abandoned append streams, blocked heartbeat workers,
  and pending snapshot reads.
  ([44dc16e7](https://github.com/databendlabs/openraft/commit/44dc16e7d29b6323a1d0d78f2203b1447ba1dcd3),
  [05043055](https://github.com/databendlabs/openraft/commit/05043055f772c85b9302923a5cc12286a730df54),
  [d5e9f334](https://github.com/databendlabs/openraft/commit/d5e9f3345d30d99e217b1d55e967a55a9d7228ff))
- The RocksDB state-machine example validates snapshot metadata before install
  and preserves recovery data if publishing a snapshot fails.
  ([afb04aa5](https://github.com/databendlabs/openraft/commit/afb04aa5d99e7d9c5be8f69387a0ad5b85ec8e31))
- The directory-transfer example reports failed final writes, refuses to overwrite
  existing target files, and rejects names that can escape the target directory
  on Windows. Binary formats can now encode chunks as byte strings, fixing
  failures with large MessagePack-encoded snapshot chunks.
  ([6fe35205](https://github.com/databendlabs/openraft/commit/6fe3520597f71faa94f46716bed983526e3e76a8),
  [e04b5df5](https://github.com/databendlabs/openraft/commit/e04b5df58198e0c3b26035cc271a557a89eff83a),
  [9dcc21ed](https://github.com/databendlabs/openraft/commit/9dcc21edd682559269cc025599db405886e0deb8),
  [c10111fb](https://github.com/databendlabs/openraft/commit/c10111fb9178835f76c9e63111ee180d400c8c79))
- Openraft no longer depends on `chrono`. Displayed timestamps now use UTC;
  the `SerdeInstant` wire format is unchanged.
  ([#2384](https://github.com/databendlabs/openraft/issues/2384))

### Upgrade tips

The examples below show what to change in your source when upgrading from
Openraft 0.10.0 to 0.10.1.

#### Pass write options to `Raft::client_write_many()`

The method now takes a `WriteOption`. Pass `WriteOption::default()` to keep
writing without specifying an expected leader.
([a8d0092b](https://github.com/databendlabs/openraft/commit/a8d0092bc850ec108f42dbfaba021f824b110094))

Before:

```rust
let responses = raft.client_write_many(entries).await?;
```

After:

```rust
use openraft::raft::WriteOption;

let responses = raft.client_write_many(entries, WriteOption::default()).await?;
```

#### Add the future type parameter to `WriteRequest`

`WriteRequest` carries an unboxed future. Direct calls such as
`raft.write(data).await` are unchanged. If a helper names `WriteRequest`, make
it generic over the future type.
([b3d8c1b6](https://github.com/databendlabs/openraft/commit/b3d8c1b6b2a0fea05efd56eb28c2ad4aeb4fbb8c))

Before:

```rust
use openraft::{RaftTypeConfig, errors::Fatal, raft::WriteRequest};

async fn submit<C>(request: WriteRequest<'_, C>) -> Result<(), Fatal<C>>
where
    C: RaftTypeConfig,
{
    request.await
}
```

After:

```rust
use std::future::Future;

use openraft::{RaftTypeConfig, errors::Fatal, raft::WriteRequest};

async fn submit<C, F>(request: WriteRequest<'_, C, F>) -> Result<(), Fatal<C>>
where
    C: RaftTypeConfig,
    F: Future<Output = Result<(), Fatal<C>>>,
{
    request.await
}
```

#### Preserve both log IDs when constructing a `Linearizer`

`Linearizer::new()` now takes the no-op log ID and the committed log ID
separately. If you send read state to a follower, replace the single
`read_log_id` field in your payload with `noop_log_id` and `committed`; take both
from the leader's linearizer via `noop_log_id()` and `committed()`.
([3b1f7fa4](https://github.com/databendlabs/openraft/commit/3b1f7fa446609727c2e5a20270ef010b49a8e011))

Before:

```rust
let linearizer = Linearizer::new(node_id, read_log_id, applied);
```

After:

```rust
let linearizer = Linearizer::new(node_id, noop_log_id, committed, applied);
```

#### Bind the owned `ReadLogId` before borrowing from it

`read_log_id()` now returns an owned `ReadLogId` instead of a reference. Keep
that value in a local variable if you borrow its inner log ID. If you used
`.clone()` to get an owned `ReadLogId`, remove it.
([3b1f7fa4](https://github.com/databendlabs/openraft/commit/3b1f7fa446609727c2e5a20270ef010b49a8e011))

Before:

```rust
let log_id = linearizer.read_log_id().log_id();
```

After:

```rust
let read_log_id = linearizer.read_log_id();
let log_id = read_log_id.log_id();
```

#### Use `try_peek()` for nonblocking reads

`PeekableReceiver::peek()` now waits asynchronously. Its previous nonblocking
behavior, including the `Result` return type, moved to `try_peek()`.
([8175ca60](https://github.com/databendlabs/openraft/commit/8175ca602330a4534a25190d9b64a182859cec9c))

Before:

```rust
let next = receiver.peek()?;
```

After:

```rust
let next = receiver.try_peek()?;
```

#### Add a fallback when matching label enums

`ExternalCommandName`, `RaftMsgName`, `NotificationName`, `CommandName`,
`SMCommandName`, `Operation`, `ErrorVerb`, and `RPCTypes` are now
`#[non_exhaustive]`. Downstream matches must handle unknown variants.
([b55c4eac](https://github.com/databendlabs/openraft/commit/b55c4eac6fa399fe5bd3703d66c298d766a59dd6))

Before:

```rust
let label = match verb {
    ErrorVerb::Read => "read",
    ErrorVerb::Write => "write",
    ErrorVerb::Seek => "seek",
    ErrorVerb::Delete => "delete",
};
```

After:

```rust
let label = match verb {
    ErrorVerb::Read => "read",
    ErrorVerb::Write => "write",
    ErrorVerb::Seek => "seek",
    ErrorVerb::Delete => "delete",
    _ => "unknown",
};
```

#### Disable automatic elections explicitly

`enable_tick: false` and `runtime_config().tick(false)` now disable only the
heartbeat timer. If you previously used either setting to suppress automatic
elections as well, also set `enable_elect: false` in `Config` or call
`runtime_config().elect(false)` at runtime.
([#2304](https://github.com/databendlabs/openraft/issues/2304))

Before:

```rust
// At startup:
let config = Config { enable_tick: false, ..Config::default() };

// Or at runtime:
raft.runtime_config().tick(false);
```

After:

```rust
// At startup:
let config = Config {
    enable_tick: false,
    enable_elect: false,
    ..Config::default()
};

// Or at runtime:
raft.runtime_config().elect(false);
raft.runtime_config().tick(false);
```

#### Calculate quorum acknowledgement age from the timestamp

On an idle leader with heartbeats off, the deprecated `millis_since_quorum_ack`
may stop updating. Use `last_quorum_acked` to calculate the age when you collect
the metric. If no timestamp is available, the calculated age is `None`; the
old field reported `Some(0)` for a leader that was its own quorum.
([43643c46](https://github.com/databendlabs/openraft/commit/43643c46ff9a3a9eb1451367d1f6e5be7017701a))

Before:

```rust
let age_ms = metrics.millis_since_quorum_ack;
```

After:

```rust
use openraft::Instant as _;

let age_ms = metrics.last_quorum_acked.map(|ts| ts.elapsed().as_millis() as u64);
```

#### Update exhaustive `Config` literals

`Config` has a new `enable_relaxed_read` field. Set it to `None` to preserve
standard reads. No change is needed for literals that already use
`..Config::default()`.
([#1267](https://github.com/databendlabs/openraft/issues/1267))

Before (unchanged fields omitted):

```rust
let config = Config {
    enable_local_lease_read: None,
    // Other existing fields.
};
```

After (unchanged fields omitted):

```rust
let config = Config {
    enable_local_lease_read: None,
    enable_relaxed_read: None,
    // Other existing fields.
};
```

#### Update manually constructed metrics

`RaftMetrics` and `RaftServerMetrics` have a new `last_leader_contact` field. Set
it to `None` when constructing a value with no known leader contact, for
example in a test fixture. Exhaustive destructuring patterns must also name the
field or use `..`.
([04cf76af](https://github.com/databendlabs/openraft/commit/04cf76af62b5cde2a49234c846be612f8c173583))

Before:

```rust
let metrics = RaftServerMetrics::<C> {
    id,
    vote,
    state,
    current_leader,
    membership_config,
    committed_membership_config,
};
```

After:

```rust
let metrics = RaftServerMetrics::<C> {
    id,
    vote,
    state,
    current_leader,
    last_leader_contact: None,
    membership_config,
    committed_membership_config,
};
```

#### Zero-pad dates in `#[since]` attributes

The date parser now requires `yyyy-mm-dd`. Pad single-digit months and days.
([#2384](https://github.com/databendlabs/openraft/issues/2384))

Before:

```rust
#[since(version = "1.0.0", date = "2026-1-5")]
pub struct Example;
```

After:

```rust
#[since(version = "1.0.0", date = "2026-01-05")]
pub struct Example;
```

#### Remove `#[add_async_trait]` from non-trait items

The attribute now rejects non-trait items in all builds. If a `single-threaded`
build previously accepted one, remove the attribute from that item.
([52d87629](https://github.com/databendlabs/openraft/commit/52d87629b5299626417ccd3970d24a756aa6305a))

Before:

```rust
#[add_async_trait]
pub struct Example;
```

After:

```rust
pub struct Example;
```
