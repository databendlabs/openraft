### Fixed:

-   Fixed: [adfee61f](https://github.com/datafuselabs/openraft/commit/adfee61f7309f33afc4c97c730e735ce10df1898) drop rocksstore and sledstore from the publish script; by Zhang Yanpo; 2026-07-28

    # Summary

    scripts/publish.sh no longer tries to publish openraft-rocksstore or
    openraft-sledstore; it now only covers macros, openraft, and
    memstore.

    # Details

    The CRATES list has carried a typo'd "rocsstore" entry since the
    script was introduced, which never matched the real rocksstore/
    directory. Under `set -euo pipefail`, resolving its manifest path
    fails and aborts the run immediately, so `sledstore` - listed right
    after it - was never actually reached either. Rather than fix the
    typo and resume publishing both crates, this removes them from
    CRATES entirely.

### Added:

-   Added: [654f32fa](https://github.com/datafuselabs/openraft/commit/654f32fae24e025ce06e568d8ce3eea4f0762157) build openraft for wasm; by Oleg Skinderev; 2026-11-06

    openraft with default features no longer enables tokio's
    `rt-multi-thread` on wasm targets, so it compiles for `wasm32-wasip1`.
    Native builds get the same tokio features as before.

    tokio emits a `compile_error!` on wasm when `rt-multi-thread` is on, and
    openraft turned it on for every target through the workspace tokio
    entry. The library itself never builds a multi-thread runtime; only the
    storage test suite does, in `testing::run_fut`, which builds a new
    runtime for each test case.

    - `rt-multi-thread` is dropped from the workspace tokio entry and comes
      back in openraft from a `cfg(not(target_family = "wasm"))` dependency
      table, the same condition tokio checks.
    - On wasm, `run_fut` builds a current-thread runtime. `Suite` documents
      what a store under test must not do on it.

    A wasm build needs Cargo's feature resolver 2, the default since
    edition 2021: resolver 1 enables the features of target-specific
    dependencies on every target.
